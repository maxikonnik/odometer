# Odometer — приборная панель лимитов Claude в меню-баре macOS

**Дата:** 2026-08-10
**Статус:** дизайн согласован, готов к планированию реализации

## Что это

Меню-бар апплет для macOS, показывающий расход лимитов подписки Claude в виде
автомобильной приборной панели: стрелочные циферблаты для лимитов, прогноз темпа
расхода и статистика токенов. Дополнительно значок мигает и подаёт звук, когда
Claude Code в терминале ждёт решения пользователя.

## Зачем

Расход лимитов сейчас виден только по команде `/usage` внутри Claude Code — то
есть нужно переключиться в терминал, прервать работу и набрать команду. Odometer
выносит эту информацию в постоянно видимое место. Вторая проблема: при работе с
Claude Code в фоне легко пропустить момент, когда агент запрашивает разрешение и
молча ждёт, — мигающий значок эту паузу устраняет.

## Область работ

**Входит:** меню-бар апплет с панелью статистики, чтение точных лимитов через
OAuth, статистика токенов из локальных логов, прогноз темпа расхода, системные
уведомления о порогах, мигание и звук при ожидании решения, автозапуск при входе,
скрипты сборки `.app` и установки хуков.

**Не входит:** виджеты Notification Center, история расхода за прошлые недели с
графиками, поддержка нескольких аккаунтов Claude, распространение через App Store,
поддержка Intel-маков и macOS младше 14.

## Технические решения

Приложение пишется на Swift 6 и SwiftUI, собирается через Swift Package Manager
командой `swift build` — без Xcode, которого на машине нет и который для этой
задачи не нужен. Скрипт `Scripts/build-app.sh` упаковывает готовый бинарник в
`Odometer.app`: создаёт структуру бандла, кладёт `Info.plist` с
`LSUIElement = true` (приложение живёт только в меню-баре, без иконки в доке) и
идентификатором `com.komo4ekk.odometer`, после чего подписывает бандл ad-hoc
подписью — она нужна, чтобы работали системные уведомления и доступ к Keychain.

Целевая платформа — macOS 14 (Sonoma) и новее, arm64.

## Архитектура

```
odometer/
├── Package.swift
├── Sources/Odometer/
│   ├── App/
│   │   ├── OdometerApp.swift        # точка входа, NSStatusItem, попап
│   │   └── AppState.swift           # @Observable агрегат состояния трёх сервисов
│   ├── Services/
│   │   ├── UsageService.swift       # OAuth → проценты лимитов
│   │   ├── KeychainReader.swift     # чтение записи Claude Code из Keychain
│   │   ├── LogsService.swift        # JSONL → статистика токенов
│   │   ├── Pricing.swift            # таблица цен моделей
│   │   ├── AttentionService.swift   # маячки хуков → мигание и звук
│   │   ├── ThresholdNotifier.swift  # уведомления о порогах
│   │   └── Settings.swift           # UserDefaults-обёртка
│   ├── UI/
│   │   ├── DashboardView.swift      # содержимое попапа
│   │   ├── GaugeView.swift          # один стрелочный прибор
│   │   ├── GaugeGeometry.swift      # чистая математика: процент → угол
│   │   ├── MenuBarIcon.swift        # отрисовка значка и его состояний
│   │   └── SettingsView.swift
│   └── Models/                      # UsageSnapshot, TokenStats, AttentionState
├── Scripts/
│   ├── build-app.sh
│   └── install-hooks.sh
├── Tests/OdometerTests/
└── docs/superpowers/specs/
```

Три сервиса полностью независимы: каждый владеет своим куском состояния и
публикует его через `@Observable`, а `AppState` только агрегирует. UI читает
агрегат и ничего не знает про источники данных. Отказ одного сервиса не влияет
на остальные.

Всё живёт в одном процессе, без фоновых демонов. Лимиты опрашиваются по таймеру,
логи дочитываются инкрементально, маячки хуков приходят через FSEvents.

Данные приложения хранятся в `~/.claude/odometer/`: подпапка `attention/` с
маячками, `cache.json` с состоянием инкрементального парсинга логов и
`odometer.log` с диагностикой. Настройки — в UserDefaults.

## Внешний вид

### Панель

Компоновка «автомобильный кластер»: большой центральный циферблат — 5-часовая
сессия (самый динамичный лимит), по бокам два меньших — недельный лимит и
недельный лимит Opus. Каждый циферблат представляет собой круг с дугой на 240°,
разделённой на три цветные зоны (зелёная до 60%, жёлтая до 80%, красная выше —
граница красной зоны совпадает с первым порогом уведомлений), делениями и
стрелкой; в центре под стрелкой — процент крупной цифрой, у
центрального прибора дополнительно время сброса мелким шрифтом.

Под приборами — строка прогноза темпа расхода вида «~8%/ч — при этом темпе сессии
хватит до 21:15». Ниже, за разделителем, — блок статистики токенов за сегодня:
суммарные токены и примерная стоимость, разбивка по моделям и по проектам.
В подвале — кнопка настроек и время последнего обновления.

Ширина панели — 330 pt.

### Темы

Панель следует системной теме macOS автоматически через
`@Environment(\.colorScheme)`. Ручного переключателя в настройках нет — он бы
только дублировал системный.

В тёмной теме циферблаты тёмные (`#141416`) со светлыми стрелками, цвета зон
яркие: `#3fb950`, `#f0b429`, `#f85149`. В светлой теме циферблаты белые
(`#fbfbfd`) с тёмными стрелками, а цвета зон берутся глубже, потому что яркие
неоновые оттенки на светлом фоне теряют контраст: `#2da44e`, `#d99117`,
`#cf222e`. Стрелка центрального прибора в обеих темах оранжевая
(`#ff6b3d` / `#d1442a`), чтобы взгляд сразу цеплялся за главный лимит.

### Значок в меню-баре

Монохромная иконка-циферблат со стрелкой, которая поворачивается по мере расхода
лимита, и рядом — процент текущей 5-часовой сессии. При входе лимита в красную
зону иконка и число краснеют. Какой именно лимит выводится числом, настраивается;
по умолчанию — сессия.

Когда Claude Code ждёт решения, значок пульсирует оранжевым примерно раз в
секунду (плавное изменение прозрачности от 100% до 25% и обратно) и в момент
появления запроса проигрывается негромкий системный звук.

## Компоненты

### UsageService — точные лимиты

Читает OAuth-токен Claude Code из Keychain (запись класса `genp` с именем сервиса
`Claude Code-credentials`) и запрашивает у сервера те же данные, что показывает
команда `/usage`: проценты трёх лимитов и времена их сброса. Опрос — раз в 60
секунд.

**Известная неопределённость:** endpoint неофициальный и не документирован.
Первой задачей реализации будет эмпирически определить его адрес и формат ответа,
наблюдая за сетевыми запросами самого Claude Code. Весь остальной код пишется
против протокола `UsageProviding`, возвращающего `UsageSnapshot`, — источник
можно заменить, не трогая UI и тесты.

При первом обращении к записи Keychain, созданной другим приложением, macOS
покажет системный запрос доступа. Это ожидаемо и разово: пользователь нажимает
«Всегда разрешать».

`UsageSnapshot` содержит: процент и время сброса для сессии, недели и Opus-недели,
а также отметку времени получения.

### LogsService — статистика токенов

Инкрементально дочитывает JSONL-транскрипты из `~/.claude/projects/**`. Для
каждого файла в `cache.json` хранится смещение прочитанного и время изменения,
поэтому при обновлении читается только новый хвост. Если файл уменьшился или его
`inode` сменился, он перечитывается целиком.

Из каждой записи извлекаются поля употребления токенов (входные, выходные,
создание кэша, чтение кэша) и модель. Дубликаты отсекаются по идентификатору
сообщения — одна и та же запись встречается в нескольких файлах при ветвлении
сессий, и без дедупликации суммы завышаются.

Стоимость считается по таблице `Pricing.swift` с ценами за миллион токенов для
известных моделей, отдельно для каждого из четырёх типов токенов. Для незнакомой
модели токены показываются, а вместо цены выводится прочерк — лучше пропуск, чем
выдуманное число.

Обновление — раз в 30 секунд и дополнительно при открытии панели.

### Прогноз темпа расхода

Считается из истории снимков `UsageSnapshot`, которые сервис держит в памяти за
текущее окно сессии. Темп — линейная аппроксимация по последним 30 минутам
наблюдений; прогноз времени исчерпания — экстраполяция до 100%.

Если наблюдений меньше 10 минут, вместо прогноза выводится «накапливаю данные».
Если темп нулевой или отрицательный (лимит не растёт), выводится «расхода нет».
Если прогнозируемое время исчерпания позже времени сброса окна, выводится
«хватит до конца сессии».

### AttentionService — мигание

`Scripts/install-hooks.sh` добавляет в `~/.claude/settings.json` три хука,
аккуратно сливая их с существующей конфигурацией (файл уже содержит настройки
пользователя и не должен перезаписываться):

- `Notification` — срабатывает, когда Claude Code запрашивает разрешение или ждёт
  ввода. Создаёт файл-маячок `~/.claude/odometer/attention/<session_id>.json`
  с идентификатором сессии, рабочей директорией, значением `TERM_PROGRAM` и
  отметкой времени.
- `UserPromptSubmit` — пользователь отправил сообщение. Удаляет маячок сессии.
- `PostToolUse` — инструмент выполнился, то есть разрешение было выдано. Удаляет
  маячок сессии.

Приложение следит за папкой `attention/` через `DispatchSource` на файловом
дескрипторе директории, поэтому реакция мгновенная и без опроса. Пока в папке
есть хотя бы один маячок — значок мигает.

Звук проигрывается один раз на появление каждого нового маячка, а не непрерывно.

Клик по мигающему значку удаляет все маячки, открывает панель и переключает фокус
на приложение-терминал, записанное в маячке (по `TERM_PROGRAM` определяется bundle
identifier, приложение активируется через `NSWorkspace`). Если терминал определить
не удалось, фокус не переключается — просто открывается панель.

Маячки старше часа подметаются при каждом пробуждении сервиса, чтобы упавшая
сессия не оставила значок мигать навсегда.

### ThresholdNotifier — уведомления о порогах

Системные уведомления через `UNUserNotificationCenter` при достижении настроенных
порогов (по умолчанию 80% и 95%) по каждому из трёх лимитов. Каждый порог
срабатывает не более одного раза за окно лимита; счётчик сбрасывается, когда
меняется время сброса окна.

Разрешение на уведомления запрашивается при первом запуске. Если пользователь
отказал или система отклонила запрос (например, из-за проблем с ad-hoc подписью),
приложение работает дальше без уведомлений, а в настройках рядом с переключателем
показывается пояснение, что уведомления запрещены в системных настройках.

### Настройки

Хранятся в UserDefaults:

- автозапуск при входе (`SMAppService.mainApp`);
- звук при запросе решения: включён/выключен и выбор системного звука;
- уведомления о порогах: включены/выключены, значения порогов;
- какой лимит показывать числом в меню-баре: сессия (по умолчанию), неделя или
  Opus-неделя.

## Отказоустойчивость

Отказ изолируется тем компонентом, к которому относится, и не гасит панель
целиком.

**Нет токена в Keychain или доступ отклонён** — приборы показывают состояние «нет
данных» (серая шкала, прочерк вместо процента) с подписью «войдите в Claude
Code»; статистика токенов из логов продолжает работать.

**Сетевая ошибка или недоступность endpoint** — приборы сохраняют последние
известные значения, в подвале серым появляется «обновлено N мин назад». Повторные
попытки идут с нарастающей паузой: 60 → 120 → 300 секунд, дальше каждые 300
секунд. Успешный ответ сбрасывает паузу к 60 секундам.

**Ответ сервера не разбирается** (формат изменился) — трактуется как
недоступность, подробность пишется в лог.

**Битая строка в JSONL** — пропускается, чтение файла продолжается.

**Нет папки `~/.claude/projects`** — блок статистики токенов показывает «нет
данных».

**`~/.claude/settings.json` повреждён** — `install-hooks.sh` завершается с
понятной ошибкой и не трогает файл.

## Тестирование

Юнит-тестами покрывается чистая логика:

- `LogsService` на фикстурных JSONL-файлах: корректность сумм по типам токенов,
  отсечение дубликатов по идентификатору сообщения, корректность инкрементального
  дочитывания (дописали хвост — прочиталось только новое), перечитывание при
  усечении файла, устойчивость к битым строкам.
- `Pricing` — расчёт стоимости для известной модели, прочерк для неизвестной.
- `UsageService` — разбор корректного ответа, поведение при ошибке разбора,
  последовательность нарастающих пауз и её сброс после успеха. Сетевой слой
  подставной, через протокол.
- `AttentionService` на временной папке: появление маячка включает мигание,
  удаление — выключает, несколько маячков от разных сессий, подметание маячков
  старше часа, однократность звука на маячок.
- `GaugeGeometry` — пересчёт процента в угол стрелки, включая границы 0 и 100 и
  значения за пределами диапазона (обрезаются, а не улетают за шкалу).
- Прогноз темпа расхода — обычный случай, недостаток данных, нулевой темп,
  исчерпание позже сброса окна.

SwiftUI-вьюхи юнит-тестами не покрываются: они проверяются глазами на собранном
приложении в обеих темах и во всех состояниях значка.

## Установка

1. `swift build -c release`
2. `Scripts/build-app.sh` — собирает `Odometer.app`
3. Скопировать `Odometer.app` в `/Applications`
4. `Scripts/install-hooks.sh` — прописывает хуки в `~/.claude/settings.json`
5. При первом запуске: разрешить доступ к Keychain и к уведомлениям

## Открытые риски

**Endpoint лимитов неофициальный** — может измениться или быть закрыт. Смягчается
изоляцией за протоколом и деградацией к статистике из логов.

**Уведомления при ad-hoc подписи** — `UNUserNotificationCenter` может отказать в
регистрации для неподписанного нормально приложения. Проверяется на раннем этапе
реализации; при отказе уведомления о порогах помечаются как недоступные, а
предупреждение о приближении к лимиту остаётся видимым через покраснение значка.
